# 5.2 ワークフロー化によるコンテキストの分散
タスクの流れを複数のステップに分割してその順序などを定義し、それぞれのステップを独立したAIエージェントやシステムで処理する
AIエージェント1つあたりのコンテキストを削減し、精度を向上させる。
- 5.2.1. ルールベース処理
AIを使う必要がない処理は、ルールベースで処理したほうが早く正確である。
- 5.2.2. シンプルなAI/ML処理
処理をエージェントから分離して「専用の小さな入出力」に閉じ込めることで、エージェントが保持、参照するコンテキストを削減しやすくなる。

- 5.2.3.　AIエージェント
ユーザーやツールの応答次第で柔軟に行動を変えたいケースで用いる
AIエージェント分割判断の観点
- 観点
    - 順序制約の強さ（絶対に守るべき手順がある）
      ワークフロー側で順序を矯正してLLMの自由度を下げ、手順誤りを構造的に防止
    - コンテキストの独立性
    　工程間のコンテキストの干渉が減り、精度が安定しやすい（局所最適化もしやすい）
    - コンテキスト量の増減
    　要約、抽出、正規化を専用ステップ化して次工程へ渡す情報を固定し、圧縮により精度の安定化とコスト削減を両立
    - ツール境界
        各ステップに渡すツール定義、指示を減らし、ツール選択ミスとコンテキスト肥大化を同時に抑制
    - 失敗時の切り戻し単位
    　失敗したステップだけ再実行でき、コストとレイテンシの増大抑制
    - 品質評価のしやすさ
    　原因切り分けが容易になり、どこで品質が崩れているか特定しやすい
    - 権限秘匿境界
    　アクセス制御、監査、マスキングを工程単位で設計でき、漏洩リスクを低減
複数のAIエージェントをコンポーネントにして処理を進めるワークフローシステムを、マルチエージェントとする事例が増えている。
- 5.2.4 ワークフロー化の注意点と弊害
AIエージェントが汎用かつ自律的にタスクを完遂できれば本来必要ない対処。
まずは単一プロンプトベースエージェントでためし、いけるところまで簡易な実装で進め、どうしても精度がでないとき一部だけワークフローの切り出しを検討する。
# 5.3 市場が期待した「AIエージェント」の正体
- 多くの企業が求めているのは本質的には作業の自動化
- 自動化のためにAIエージェントが期待されバズワード的に広まった
- 動的判断ですべてを完結させることが難しく、ワークフロー化が採用されることになった
- 現在ではワークフローまで含めた自動化が広義にマルチエージェントと呼ばれるようになった

作業の自動化を実現するために「ルールベース処理」「シンプルなAI/ML処理」「AIエージェント」などをパーツとしたワークフローシステムの開発の責務が増えてくる。

# 5.6 コンテキスト肥大化に伴うその他の課題と対策
- 5.6.1 ツール定義の肥大化
Tool search tool
使いもしない大きなコンテキストを持ちづづけることは性能劣化を誘発するリスクがあるのでその対策。
- Skillの活用による段階的コンテキストロード
サンプルシナリオにおけるSkillの活用
- Skillの意義と注意点
メインエージェントがコンテキストを獲得するので、ロードなどでコンテキストが圧迫され性能劣化につながる。
Skilの実行が積み上がっていくほどコンテキストのロードが進んでいくので、複数Skillを連続で呼び出すようなケースはコンテキストが肥大化する。
エージェント分割でコンテキストを分離する対策が有利になる。（一方生成難易度も高い）
- コンテキストの使い方から見るSkillと関連キーワードの違い
MCP/Skills/エージェント分割
- MCP:コンテキスト肥大化のリスクが最も高い
- Skill:メインエージェントにある程度コンテキストが載ってもいいが多段で複雑なサブタスク、エージェント分割はそれも許容できないような比較的重厚なサブタスクになる。
